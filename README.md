# finish-session - скилл «Завершение сеанса» для Claude Code

**Скилл закрывает рабочую сессию за тебя, вместо того чтобы задавать пять вопросов подряд.**

## Проблема, которую он решает

Знакомый финал работы в Claude Code:

> - Код готов. Закоммитить?
> - *да*
> - Готово. Такое сообщение коммита подойдёт?
> - *да*
> - Запушить в main?
> - *да*
> - Удалить временную ветку?
> - *да*
> - Записать ретроспективу?

Пять сообщений на то, что и так было понятно с самого начала. Если открыто пять окон на пять
задач - это двадцать пять переключений внимания на ровном месте, и каждое выбивает из работы.

Сказать «делай всё сам» тоже не выход: агент может увезти на прод чужой незакоммиченный код из
соседнего окна, снести ветку, которую занял другой чат, выкатить то, что ждало проверки, или
запушить `.env` в публичный репозиторий. Отменить это уже нельзя.

## Что делает скилл

Разводит эти два случая. Сначала - дешёвые механические проверки: что уедет вместе со мной, чьё
это, не ждёт ли работа вердикта, нет ли секрета в коммитах. И только там, где проверка дала
однозначное «да», агент действует молча.

Всё остальное собирается в **один блок вопросов**, который задаётся ровно один раз - и чаще всего
он пустой. В конце приходит одно сообщение: что теперь работает, что уехало, что требует твоих
рук. Последняя строка - «Сеанс закрыт, чат можно архивировать».

## Установка

```bash
git clone https://github.com/dimaffg7-spec/finish-session.git
cp -r finish-session/skills/finish-session ~/.claude/skills/
```

Скилл станет доступен в новой сессии. Проверить - команда `/finish-session`.

Никаких зависимостей: это один markdown-файл, никакого кода, ничего не устанавливается и не
запускается фоном.

## Как пользоваться

Скажи в конце работы любое из:

- «завершение сеанса»
- «заверши сеанс»
- «закрываем чат»
- «сдай работу»
- `/finish-session`

Дальше агент идёт по девяти шагам сам.

## Настройка: до какого шага агент идёт молча

**По умолчанию скилл НЕ пушит и НЕ деплоит без подтверждения.** Он доводит работу до коммита,
а push / merge / deploy складывает в единый блок вопросов.

Если хочешь полную автономность до прода, добавь в `CLAUDE.md` своего проекта строку:

```
finish-session: автономный push разрешён. Прод-ветка: main
```

Прод-ветку указывай явно: она далеко не всегда `main`, а угадывать агенту запрещено.

Остальное скилл читает из твоего проекта: список гейтов из `package.json` / `Makefile` /
`pyproject.toml`, конвенции бэклога и ретроспектив - из твоего `CLAUDE.md`. Своих конвенций он
не навязывает: чего в проекте нет, то и не делается.

## Что скилл делает

| Шаг | Что происходит |
|---|---|
| 0 | Шесть предохранителей: надо ли выкатывать · что уедет вместе со мной · не снесу ли чужое · не мешаю ли соседним окнам · красные гейты · не утечёт ли секрет |
| 1 | Разведка: ветка, worktree, план, бэклог, разрешение на push |
| 2 | Гейты одним заходом, список читается из проекта |
| 3 | Единственная точка вопроса - всё накопленное разом |
| 4 | Коммит `git add` поимённо |
| 5 | Мерж и push, включая обход при грязном главном дереве |
| 6 | Подтверждение, что сборка доехала, а не просто «запушено» |
| 7 | Уборка только своего, каждое после явной проверки |
| 8 | Следы: бэклог, план, ретроспектива, память проекта |
| 9 | Финал одним ходом |

## Безопасность

Что скилл **не делает никогда**:

- не пушит и не деплоит, пока это не разрешено строкой в `CLAUDE.md` или подтверждением;
- не делает `git add .` и `git add -A` - только поимённо, чтобы не утащить незаконченные правки
  соседнего окна;
- не удаляет ничего, что не создал сам в этой же сессии, и каждое удаление проверяет отдельно;
- не везёт на прод чужой незапушенный код;
- не запускает опасную команду, чтобы «проверить, откажется ли система».

Отдельный гейт стоит на секретах: перед push проверяются имена файлов в своих коммитах на
`.env`, ключи и `secrets.*`. Push назад не отменяется - хостинг хранит объект даже после
`--force`, и ключ считается скомпрометированным.

Два предохранителя, где легче всего ошибиться, устроены fail-safe: неизвестное расширение файла
считается кодом, а не документацией, и сомнение на любом пункте уборки означает «не удалять».
Оставленный мусор дешевле снесённой чужой работы.

## Что стоит понимать до установки

Скилл написан под работу в нескольких параллельных окнах Claude Code на одном репозитории - отсюда
проверки на чужие ветки, чужие worktree и грязное главное дерево. В одиночном проекте часть шагов
просто не сработает, и это нормально.

Скилл не заменяет ревью. Он закрывает сессию, а не подтверждает, что код хороший.
